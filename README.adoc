= FPSOT style specification

Rules for the visual look of the screens of FPSOT products: design tokens in the Design Tokens Format Module 2025.10, component states, errors, loading and empty states, destructive actions, and themes.
The FPSOT default theme is PatternFly as published. The Québec theme follows the Système de design gouvernemental, and the Canada theme follows the GC Design System and Canada.ca.
Every accessibility value comes from the FPSOT accessibility specification.
Version 0.1 is a draft.

== Implement this spec

Read the normative text in `spec/en/` or `spec/fr/`.
Start with `index.adoc`, then read the seven parts.
Each requirement has an ID from `STY-001` to `STY-065`.
A product checks its screens against every MUST rule on tokens, components and destructive actions.
A theme checks itself against every MUST rule on themes and on checking a theme, and publishes its check record.

== Adopt this spec

Read the guide in `docs/modules/en/pages/index.adoc` or `docs/modules/fr/pages/index.adoc`.
It shows how to build a theme for a jurisdiction and check it before release.
A government body chooses the theme of its jurisdiction, adds its own marks in the header and footer, and records any binding behavior rule that differs from this spec.
The comparison pages show how the design systems of Canada and Québec relate to each requirement.

== Layout

[cols="1,3"]
|===
| Folder | Content

| `spec/`
| Normative text, in English and French. `book.adoc` joins the pages into one book.

| `docs/`
| Guides, in the Antora folder layout.

| `skill/`
| The agent skill: a short summary that cites requirement IDs.

| `rules/`
| Machine-checkable rules. None yet.

| `diagrams/`
| PlantUML sources and their rendered SVG files. None yet.

| `jurisdictions/`
| Comparison data: the international baseline, Canada and Québec.
|===
